## 1. 一句话定位

**Playtest Agent** 是一个游戏的质量保障基础设施：它自己注册房间、自己开局、自己按策略玩，
为每一步产出**治理证据**（幂等指纹 / 成本归因 / traceId），并输出**可复现**的缺陷报告。

`Node.js 24` · `TypeScript 5.5` · **运行时零依赖**

---

## 2. 目标用户

**独立开发者 / 小团队的游戏作者**，特征：

- 手上有 1 个以上**自己的**网页游戏（浏览器 + HTTP API），没有专职 QA；
- 已经在用 AI 辅助开发，但**质量验证仍靠人工试玩**；
- 知道人工试玩的两个硬约束：**要找到没接触过项目的人**、**只能覆盖一次、不可复现**。

**不是**的目标用户：3A 工作室、商业 QA 团队、引擎内游戏（Unity / Unreal）开发者。

---

## 3. 反定位：我们明确不是什么

| 不是什么                           | 为什么                                                                 |
| ---------------------------------- | ---------------------------------------------------------------------- |
| **不是取代 QA / 人工试玩**         | 机器证不了"人看着不难受"。二者**串联**：机器没过的，不该浪费真人注意力 |
| **不是性能测试 / 压测工具**        | 只测机制正确性，不测吞吐与延迟                                         |
| **不是视觉回归工具**               | 走 HTTP API + 状态断言。像素是噪声源，游戏状态才是权威源               |
| **不是通用爬虫 / 任意输入 fuzzer** | 动作来自合法动作集；越界输入由契约测试单独覆盖                         |
| **不是游戏本体**                   | 它是**工具**，被测游戏在另一个仓库                                     |
| **不追求"AI 棋力超过 minimax"**    | 策略层的价值是**探索与复现**，不是下得更好                             |

## 4. 问题陈述

### 4.1 现状

现有 15 个项目里，7 款游戏的质量验证依赖两件事：
**单元测试 + Playwright 脚本化 e2e**。两者能覆盖"已知路径"，但：

- **覆盖不到未知路径** —— 脚本是人写的，只测人想到的地方；
- **测不到并发** —— 一个人不会同时落两手；
- **测不到"跑了一半崩了"** —— CI 重跑是从头再来，不续跑。

### 4.2 真实案例（本仓库内的证据）

`othello-online/tests/playtest/` 有一整套**真人试玩执行手册**（话术、时间盒、观察表），
但 `phase6-verdict.md` 判定 **CONCERNS**，原因之一是：

> 「真人试玩没有执行。原因是**被试不可得**——约不到一个"没接触过这个项目的人"。」

而同一份文档也写明：

> 「**自动化只能证明"数据一致"，证明不了"人看着不难受"。**」

→ **机器能补上"数据一致"那一半，且这一半目前是空的。**

### 4.3 外部证据

调研（[`research/2026-11-03-竞品与自动测试现状.md`](research/2026-11-03-竞品与自动测试现状.md)）显示：

- 学术侧有 TITAN（MMORPG）、人机对照研究（800 用例 / 276 人）；
- 商业侧有 Razer QA Companion-AI（GDC 2026）、modl.ai；
- 开源侧有 `ysskrishna/ai-game-playtesting-agent`（GPT-4o vision + Playwright + LangGraph，2048）。

**但：全部来源均未涉及"每步幂等 / 成本归因 / 崩溃续跑"这一层，且均未公布单次运行成本与方差。**

## 5. 差异化支柱（四条，每条都必须能被验收）

| 支柱                              | 内容                                                              | 验收方式                                                      | 状态               |
| --------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------- | ------------------ |
| **支柱一：自主开局**              | 不需要人工摆姿势 —— 自己建房、自己入座、自己开走                  | `npm run playtest -- --scenario smoke` 产出完整 StepRecord 链 | ✅ 59 步全自动     |
| **支柱二：确定性可复现**          | 同 seed + 同局面 → 同动作；缺陷能稳定复现                         | 同 seed 跑两次，动作序列**逐项相等**                          | ✅ 集成测试断言    |
| **支柱三：崩溃续跑不重复副作用**  | 崩在"动作已生效、检查点未落" → 续跑**不产生第二次副作用**         | 注入崩溃 → 续跑 → 副作用计数与基线逐项相等                    | ✅ 集成测试通过    |
| **支柱四：降级不中断 + 如实标注** | 模型不可用 → 降级到确定性基线，**仍跑完整局**，报告显式标注降级段 | 无端点时跑完 N 步，报告「降级说明」非空                       | ✅ 60 步全标注降级 |

## 6. 核心工作流（六段式）

```
① 场景定义 Scenario      跑什么：开局、策略、步数上限、预算
        ↓
② 驱动循环 GameDriver     观察 → 决策 → 动作 → 观察 → …
        ↓                        ↑
③ 治理接入 Governance     幂等调用 / 成本归因 / traceId / 续跑
        ↓
④ 断言 Oracle             通用断言 + 游戏特异断言 → 违规项
        ↓
⑤ 记录 StepRecord         每步的完整证据（指纹/耗时/结果/治理）
        ↓
⑥ 报告 Reporter            Markdown + JSON（可 diff、可入库）
```

**循环形状**：本项目是**循环**，aiwarden 是**固定 DAG**。两者形状不同，
本项目只进程外消费 aiwarden 的治理能力，**不复用** `AgentDagEngine`。

## 7. 游戏适配器契约（SPI）

```ts
interface GameAdapter {
  readonly name: string;
  open(params: { seed: number }): Promise<{ state: GameState; token: string }>;
  resume?(params: { token: string }): Promise<{ state: GameState } | null>; // 可选
  observe(params: { state: GameState; token: string }): Promise<Observation>;
  act(params: { state: GameState; token: string; action: Action }): Promise<{
    ok: boolean;
    observation?: Observation;
    error?: string;
  }>;
  isTerminal(params: { state: GameState }): boolean;
}
```

**硬约束**：

1. **适配器只读被测游戏** —— 既有游戏零改动（红线 2.2）；
2. **合法动作集由适配器独立计算** —— 不复用被测游戏的规则代码，
   否则"用游戏自己的规则校验游戏自己"会漏掉共模错误；
3. **必须过契约测试套件**（`src/adapter/contract-suite.ts`），7 条用例。

**首个适配器**：`othello-local` —— 打 othello-online 的本地 `preview`（内存版 `/api`），
**零云端依赖**。

## 8. 策略层契约（SPI）

```ts
interface Strategy {
  readonly name: string;
  decide(params: { observation: Observation; seed: number }): Promise<Decision>;
}
```

**两个实现**：

| 实现                | 用途                                          | 确定性                                       |
| ------------------- | --------------------------------------------- | -------------------------------------------- |
| `HeuristicStrategy` | 确定性基线；降级目标；探索走法                | ✅ 同 seed → 同序列（PRNG 按 seed 缓存实例） |
| `LlmStrategy`       | 模型决策（OpenAI 兼容）；不可用时**显式降级** | 模型输出受限：只能从合法动作集里选           |

**降级语义（不可协商）**：

- 无端点 / 超时 / 配额耗尽 / 模型返回越界动作 → `degraded: true` + `degradedReason`；
- 降级后**必须仍返回合法动作**（游戏仍可玩）；
- **绝不静默降级** —— 悄悄换个策略假装无事发生，等于报告里的降级信息是假的。

**模型只做决策与表达，断言层裁决 pass/fail**（外部印证见调研 §4.1-1）。

---

## 9. Oracle 断言模型

**分层**：

| 层               | 内容                                                                                       | 谁写                                 |
| ---------------- | ------------------------------------------------------------------------------------------ | ------------------------------------ |
| **通用断言**     | 回合切换后新执子方须有合法动作；失败动作不得改变状态；观察序号不得回退；终局不得有合法动作 | 本项目（`generic.ts`）               |
| **游戏特异断言** | 合法着法、翻转数量、棋子守恒、moveCount 递增、跳过规则                                     | 每个游戏的适配器作者（`othello.ts`） |

**为什么分层**：通用层**无法**区分"合法跳过"与"该换没换" ——
`legalActions` 永远属于当前执子方，两种情况形状完全相同。
**硬判就是误报**（本项目实际踩过一次，见 §9.1）。

**独立性纪律**：特异断言**不复用**被测游戏的规则实现，独立重写。

### 9.1 一次真实的误报（记录在此，因为比假缺陷更有价值）

- **现象**：seed=123 报 `G1-turn-did-not-alternate`（致命）。
- **查证**：othello 规则允许"对方无子可下 → 保持当前回合"（`gameLogic.ts:296-303`），
  白方跳过黑方后**白方自己仍有子可下**，这是**合法**的。
- **修正**：通用层不再判"回合必须交替"；跳过规则交给游戏特异断言（OTH6）；
  通用层只保留"回合切换后新执子方须有合法动作"（可通用判的那一条）。
- **代价**：通用层少判了一条 —— 但**换来零误报**，而误报会让整个报告失去可信度。

## 10. 治理接入模型

### 10.1 幂等键构成（冻结契约 ⑦）

```
幂等键 = { businessKey } :: { session } :: { stepNo } :: { digest }
digest  = sha256(canonicalize({ stepNo, payload })).slice(0, 32)
```

- `businessKey` = 对局标识（房间码）
- `session` = 本次运行的 session key
- `digest` = 动作内容摘要（键序无关；数组保序；`undefined` 丢弃；`NaN → null`）

**stepNo 必须参与摘要** —— 否则"第 3 步与第 7 步做了同一个动作"会撞键，
续跑时会误判为重放而跳过真实动作。（本项目在单测阶段抓到并修正过。）

### 10.2 关键语义

| 语义     | 规则                                                        | 对齐                    |
| -------- | ----------------------------------------------------------- | ----------------------- |
| 动作幂等 | 同键重放 → `replayed: true`，**不产生第二次副作用**         | aiwarden ADR-013 决策 6 |
| 崩溃续跑 | 崩在"动作已生效、检查点未落" → 续跑重做该步，幂等键命中终态 | 同上（双防线）          |
| 租约独占 | 同 session 并发 → 409，不并行产生副作用                     | ADR-013 决策 4          |
| 成本归因 | 四维：租户 / 会话 / 步骤 / 工具                             | ADR-014                 |
| 替身等价 | 内存替身与真实 HTTP 实现跑**同一套**契约测试                | 本项目红线              |

### 10.3 两种治理客户端

| 实现                       | 用途                                                          | 状态                                       |
| -------------------------- | ------------------------------------------------------------- | ------------------------------------------ |
| `InMemoryGovernanceClient` | 单测 / 契约测试 / 无 Docker 时                                | ✅ 已实现                                  |
| `AiwardenHttpClient`       | 对接真实 aiwarden（`POST /api/v1/agent/tools/{tool}/invoke`） | ✅ 已实现，**本机未实跑**（Docker 不可用） |

**aiwarden 零改动** —— 只消费既有边界。身份头取自源码常量
（`X-Aiwarden-Tenant-Id` / `X-Aiwarden-User-Id`），不是猜的。

## 11. 报告格式

**两份**：

- `reports/<scenario>-<timestamp>.md` —— 人类读（概览表 / 发现表 / 步骤表 / 降级说明）
- `reports/<scenario>-<timestamp>.json` —— 机器读（`schemaVersion: 1`，冻结契约 ⑧）

**发现项编号**（稳定，跨次运行可对照）：

- 通用断言：`G<n>-<描述>`（如 `G1-new-turn-has-no-legal-moves`）
- 游戏特异断言：`<游戏缩写><n>-<描述>`（如 `OTH6-turn-should-have-switched`）

编号体系与 `othello-online/tests/playtest/smoke-checklist.md` 对齐 ——
机器结果能直接接人工观察表。
