## 1. 调研说明

### 1.1 调研对象与前提

**要回答的问题**：「AI 自主玩游戏来做游戏测试」这个方向，是**挤爆**了还是**还有空位**？
如果挤爆了，`playtest-agent` 就不该立项（门 G1 的止损条件）。

**前提**：

- 本项目是**独立开发者自用**的工具，不是商业 QA 产品；
- 被测对象是**自己的网页游戏**（浏览器 + HTTP API），不是 3A 引擎游戏；
- 目标是「把游戏质量验证从人工试玩变成可重复的自动化证据链」。

### 1.2 方法

- 检索：web 搜索（英文关键词），优先一手来源（论文、官方文档、公开仓库）；
- 二手综述（如博客）**只作线索**，其转述的数字一律降级为「二手转述」，不当作结论；
- **没有实测任何竞品** —— 本文所有数字都标明来源与证据等级。

### 1.3 检索关键词

`LLM agent automated game testing 2026` / `AI playtesting agent vision model browser games` /
`AI game testing agent reinforcement learning playtest autonomous` / `automated game testing benchmark`

### 1.4 一句话结论

> **方向不挤爆，但"给个人开发者用的、治理证据完整的最小可用版本"仍是空位。**
> 学术侧有大规模研究（TITAN / MMORPG），商业侧有厂商产品（Razer QA Companion-AI / modl.ai），
> 开源侧有一个公开的 2048 视觉 Agent 示例 —— **但三者都没有"每一步都有幂等/成本/trace 证据、
> 崩溃后续跑不重复副作用"这一层**。那正是本项目要占的位置。

## 3. 竞品全景

### 3.1 学术侧：LLM Agent 做游戏测试

| 项目                                              | 层级     | 核心信息                                                                                                                                        | 证据等级                                              |
| ------------------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| **TITAN**（LLM-agent 框架，面向 MMORPG 自动测试） | 论文自报 | 95% 任务完成率；发现 **4 个此前未知的 bug**；已用于 **8 条真实 QA 流水线**                                                                      | **A**（数字为论文自报，未独立复现）                   |
| **人机对照研究**（800 个测试用例 / 276 名参与者） | 论文自报 | GPT-4o 场景描述准确率 **87.5%**；缺陷检出率 **97.1%**；AI 辅助测试者准确率 **62.7%** vs 纯人工 **41.3%**（p<0.001）；"知识 + AI" 组合 **64.4%** | **A**                                                 |
| **DRL 增强自动游戏测试**                          | 论文自报 | 至少从 2021 年起，深度强化学习已在增强自动游戏测试                                                                                              | **A**（经 D 来源转述，原始论文未直接查阅 → 降级处理） |

**关键读法**（这是本文最重要的一段）：

> 这些数字**不能**直接搬到本项目上。原因按来源自己的说法有三条：
> ① 最强的数字来自**大规模 MMORPG 框架**与**受控真人研究**，不是小型 canvas 游戏；
> ② 人机研究的 **87.5% 场景描述准确率意味着 GPT-4o 大约每八次描述错一次**；
> ③ **没有任何来源公布单次运行的成本或运行间方差** —— 缺就写缺，不拿估计值填。

→ 所以本项目**不设"缺陷检出率"这类指标**（拿不到可信基线），只设**可复现性**与**证据完整性**指标。

### 3.2 商业侧：厂商产品

| 产品                                       | 能力描述                                                                                                                                                 | 明说的限制                                                                           | 证据等级 |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | -------- |
| **Razer QA Companion-AI**（GDC 2026 发布） | 接受 prompt 或游戏设计文档生成测试计划；**自主游戏 Agent 会选一个测试、玩它、比对预期与实际、返回 pass/fail**；基于视觉的缺陷检测；宣称 zero-integration | 官方公告只有能力描述，**无独立 benchmark**                                           | **B**    |
| **modl.ai**                                | 无需集成的黑盒 Agent；视觉 + OCR + 自然语言测试任务；**每游戏定制训练模型**；CI 集成；按严重度分级的报告；Android / 桌面支持                             | **官方自述**：极快或时间敏感型玩法**尚不完全支持**；"无需集成"≠ 免训练、≠ 与时间无关 | **B**    |

**读法**：Razer 描述的循环 —— _选测试 → 玩它 → 比对预期与实际 → 返回 pass/fail_ ——
与本项目的 `observe → decide → act → assert → report` **同构**。
本项目的差异不在循环形状，而在**证据层**（见 §5）。

### 3.3 开源侧：一个可直接借鉴的公开实现

| 项目                                       | 内容                                                                                    | 证据等级                                      |
| ------------------------------------------ | --------------------------------------------------------------------------------------- | --------------------------------------------- |
| **`ysskrishna/ai-game-playtesting-agent`** | 用 **GPT-4o vision + Playwright + LangGraph** 玩 2048；**不解析 DOM**，直接看浏览器像素 | **C**（公开实现示例，**不是**独立 benchmark） |
| **Playwright 视觉回归**                    | `toHaveScreenshot` + `maxDiffPixels`（pixelmatch）；`toMatchAriaSnapshot` 做语义快照    | **B**（官方文档）                             |

### 3.4 学术索引：领域活跃度的旁证

**`Scriptwonder/awesome-game-gen`** —— 80 篇论文的策展清单（2026-06-17 更新，覆盖 2023-02 → 2026-06），
按两个轴打标签：**Layer**（Generation / Evaluation / Survey / hybrid）与
**Surface**（Unity / Unreal / Godot / Web-GUI / 3D / symbolic / PCG / engine-native 等）。

清单里已单独成节的板块：

- **Automated Game Testing & Playtesting**
- **Game-Playing Agent Benchmarks（eval the player）** ← 与本项目最相关
- **MCP Benchmarks（sibling protocols）**
- **Procedural Content Generation Benchmarks**

→ **"评估玩家"与"自动游戏测试"已经是独立的 benchmark 品类**，说明方向活跃、有生态，
不是无人区。

## 4. 可借鉴 / 需规避 / 待验证

### 4.1 可借鉴（直接吸收进设计）

| #   | 来源                      | 借鉴点                                                           | 落在本项目哪里                                                                           |
| --- | ------------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 1   | 公开 2048 实现 + 综述结论 | **「用 AI 检视与解释；让确定性检查负责 pass/fail」**             | 模型只做**决策与表达**；**Oracle 断言层裁决**。模型不得取代确定性检查                    |
| 2   | 同上                      | **「模型不应臆造选择器、不应解释应用内部」**                     | 模型的输入只有**合法动作集**，输出必须落在其中；越界即降级（`LlmStrategy` 已实现）       |
| 3   | Razer 描述的循环          | observe → decide → act → compare → report                        | `GameDriver` 的循环形状（**但本项目是循环，aiwarden 是 DAG**）                           |
| 4   | 人机研究                  | 视觉模型**约 1/8 场景描述是错的** → 不能当唯一权威               | 断言层与模型层**分离**；模型降级不影响判定                                               |
| 5   | 综述的结论                | **「AI playtesting agents 是起点，不是完全验证过的 QA 替代品」** | 本项目的定位表述必须**保守**：是"机器能测的那一半"，不是"取代 QA"                        |
| 6   | modl.ai 自述限制          | 极快 / 时间敏感型玩法难以覆盖                                    | 本项目**不追求**覆盖实时动作类游戏（见 §5 边界）                                         |
| 7   | 全部来源                  | **无人公布单次运行成本 / 方差**                                  | 本项目把**成本归因**做成产品能力（每步带 tokens + traceId）—— 这是现成工具都没给出的东西 |

### 4.2 需规避

| #   | 风险                             | 规避做法                                                                       |
| --- | -------------------------------- | ------------------------------------------------------------------------------ |
| 1   | **视觉优先**（只看像素不看 DOM） | 本项目走 **HTTP API + 状态断言**，不看像素。游戏状态是权威源，视觉反而是噪声源 |
| 2   | **让模型判 pass/fail**           | Oracle 断言层裁决，模型只提供动作与解释                                        |
| 3   | **每游戏定制训练模型**           | 通用模型 + 确定性基线；不训练                                                  |
| 4   | **把厂商自报数字当自己的**       | 本项目的验收标准全部是**自己实跑的可复现命令**，不引用外部百分比               |
| 5   | **声称"取代 QA"**                | 定位为"补上机器能测的那一半"，与人工试玩串联                                   |

### 4.3 待验证（本次未能验证，明确标注）

| #   | 待验证项                         | 为什么没验               | 怎么验                                                             |
| --- | -------------------------------- | ------------------------ | ------------------------------------------------------------------ |
| 1   | **单次运行的真实成本**           | 全部来源均未公布         | 本项目接入真实模型后**自己实测**，并写进报告（每步 tokens 已采集） |
| 2   | **运行间方差**                   | 同上                     | 同 seed 跑 N 次比对报告 diff（本项目已实现确定性，可直接验）       |
| 3   | **TITAN / 人机研究的原始数据**   | 二手转述，未查阅原始论文 | 若要在作品集引用精确数字，须读原文                                 |
| 4   | **Razer / modl.ai 的实际表现**   | 需付费账号 + 实际游戏    | 不做（商用品不在本项目目标用户范围）                               |
| 5   | **公开 2048 实现的实际代码质量** | 未克隆阅读               | 可作为后续"抄架构不抄代码"的对照                                   |

## 5. 本项目在竞品图景中的位置

```
                 证据完整性（幂等 / 成本归因 / trace / 崩溃续跑）
                                    ↑
                                    │
                    ┌───────────────┴───────────────┐
                    │   ★ 本项目（playtest-agent）    │
                    │   个人开发者自用 · 治理证据完整    │
                    └───────────────┬───────────────┘
                                    │
   大规模研究（TITAN）──── 商业产品（Razer / modl.ai）── 公开实现（2048）
        强证据 / 不可及          有能力 / 需付费 / 无独立benchmark    架构可借鉴 / 无治理
```

**一句话差异化**：

> 现成方案要么规模够不着（MMORPG 研究）、要么要付费且证据不可查（商业产品）、
> 要么只有架构没有证据链（公开实现）。
> **本项目是唯一把"每一步的幂等、成本归因、trace、崩溃续跑"做进游戏自动测试的一层** ——
> 它来自一个现成的、已被实测过的治理组件（aiwarden），而不是从零造。

## 6. 饱和度判断（门 G1 的判据）

| 判据                                   | 结论   | 依据                                           |
| -------------------------------------- | ------ | ---------------------------------------------- |
| 学术热度                               | **高** | 独立 benchmark 品类 + 80 篇策展清单（2026-06） |
| 商业供给                               | **中** | 两家明确产品，均为 2026 前后                   |
| 开源供给                               | **低** | 检索到的可读实现基本是示例级（2048）           |
| **面向个人开发者的"治理证据完整"版本** | **空** | 全部来源均未涉及幂等 / 成本归因 / 崩溃续跑     |

**结论：不挤爆，且空位明确。→ 通过门 G1，继续立项。**

但同时要诚实标注：**"空位"不等于"有价值"**。
本项目的价值必须由**自己的可复现证据**支撑（Stage 6 的验收），而不是靠这个判断。
