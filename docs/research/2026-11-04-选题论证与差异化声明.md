## 二、三个候选方向与打分

| 方向                       | 复用既有资产                                                         | 两周内可验证                    | 需新建宿主         | 品类补位（03 类）                | 合计      |
| -------------------------- | -------------------------------------------------------------------- | ------------------------------- | ------------------ | -------------------------------- | --------- |
| **A · 通识局加"老师 NPC"** | **高** —— 已有 provider / zod 校验 / PRNG / 12 域题库 / mastery 数据 | **能**                          | **不需要**         | 中上（有角色、有记忆、影响玩法） | **★★★★☆** |
| B · 新造一款叙事游戏       | 低                                                                   | 难（引擎 + 玩法 + 内容 + 美术） | **需要**           | 完整                             | ★★☆☆☆     |
| C · 独立 NPC 框架库        | 中                                                                   | 能                              | 需要（否则是零件） | 弱                               | ★★☆☆☆     |

### 为什么选 A

1. **它是唯一"NPC 的能力 = 游戏的核心玩法需求"的选择** —— 通识局定位是"12 域知识闯关"，
   **"针对你薄弱域出题"本就是它最自然的下一步**，不是硬塞进去的功能。
2. **它同时补两件事**：① 作品集缺 03 类；② 通识局自己的短板 ——
   **"影子对手"只跟昨天比，没有针对性**（`docs/GAME-RULES.md`）。
   **NPC 老师 = 影子对手的"有记忆"版本**。
3. **技术栈完全同构**（Next.js 14 + TS + Tailwind），且通识局**已有运行时 AI 基础设施**
   （`lib/ai/provider.ts` 的 OpenAI 兼容 + Ollama 双后端 + `parseJsonLoose` + zod 校验）
   → **NPC 的 LLM 接入层几乎零成本**。
4. **改动可控**：新增 `lib/npc/` + 一个对话入口，**不动 `lib/engine/*`**。
5. **传播性**：结果可分享（"我的 NPC 老师说我知识形状是倒三角"）。

### 为什么暂不做 B、C

- **B（新造叙事游戏）**：把工作量从"引擎层"膨胀到"完整游戏"，
  而灵感库 03 的定义是「**让角色有记忆，让选择改变故事**」——
  这是**引擎能力**的要求，不是"要做一款新游戏类型"的要求。**读成后者是过度解读。**
- **C（独立库）**：没有宿主就是"零件"不是"作品"。

## 三、项目定义

### 3.1 名称与定位

**名称**：`tongshi-ju` 的 **老师 NPC**（内部代号 `lib/npc/`）
**定位**：**一个记住你薄弱域、并据此出题与点评的 AI 老师**——
不是聊天挂件，而是**难度调节器**。

### 3.2 五条确定性承诺

> 每条必须有**可复现的验证命令 + 期望输出**（PRD §13 落地）。

| #      | 承诺                                                             | 验证方式                                                        |
| ------ | ---------------------------------------------------------------- | --------------------------------------------------------------- |
| **N1** | NPC **记住**你的薄弱域：连续答错某域后，下次该域出题概率显著上升 | 固定 seed 跑两组（对照组不答错 / 实验组答错），断言选域分布差异 |
| **N2** | NPC **影响玩法**：它的选域决策真的改变了每日题集，不只是陪聊     | 断言 NPC 决策后 `buildDailySet` 的域集合与基线不同              |
| **N3** | **降级不崩**：无模型端点时，NPC 仍出题、仍点评，报告标注降级段   | `AI_API_KEY=` 跑一遍，断言 `degraded === true` 且题集正常产出   |
| **N4** | **每次对话有治理证据**：token 消耗 + traceId + 幂等键可查        | 查 `t_llm_call_log` / 报告的 `governance` 段                    |
| **N5** | **可复现**：同 seed + 同答题序列 → 同选域、同台词                | 同 seed 跑两次，断言决策序列逐项相等                            |

### 3.3 反定位：明确不是什么

| 不是什么           | 为什么                                                    |
| ------------------ | --------------------------------------------------------- |
| **不是聊天机器人** | NPC 不接受自由聊天；它的输出是**选域 + 点评**（受控接口） |
| **不是剧情引擎**   | 通识局是知识闯关，不做分支叙事                            |
| **不是新的游戏**   | 是既有游戏的**玩法增强**                                  |
| **不改既有引擎**   | `lib/engine/*` 零改动                                     |
| **不做向量数据库** | 通识局的"相关"是结构化的（见调研 §5.1）                   |
| **不做反思机制**   | 反思是拟人度增强，不是本项目的差异化（调研 §5.3）         |

## 四、差异化声明

### 4.1 「已有 NPC 记忆框架和大量 AI 角色产品，为什么还要这个？」

调研结论（§6.1）：**架构层已成熟** —— Generative Agents 的三段检索已成"reference design"，
分层记忆有大量公开实现。**光有这套架构不构成差异化。**

| 已有方案                   | 缺什么                               | 本项目补什么                            |
| -------------------------- | ------------------------------------ | --------------------------------------- |
| Generative Agents 式记忆流 | 无成本治理；NPC 的每次交互是"免费"的 | 每次对话有**成本归因 + 幂等键 + trace** |
| 分层记忆工程实现           | 无从验证"记得对不对"                 | **同 seed 可复现** → 记忆行为可断言     |
| 商业 AI 角色产品           | 成本不可见；长会话成本失控           | **预算熔断 + 审计留痕**                 |
| 传统对话树 / 任务旗标      | 记不住                               | 记得住，**且知道花了多少钱**            |

### 4.2 一句话差异化

> **别人做"AI 帮你记住"，本项目做"AI 帮你记住，而且每一次记忆和每一句话都留下可审计、可复现、可限流的证据"。**

### 4.3 交叉验证：关键设计的外部印证

| 本项目的设计                       | 外部印证                                              | 证据等级                                |
| ---------------------------------- | ----------------------------------------------------- | --------------------------------------- |
| 三段检索（近因 + 重要度 + 相关性） | Generative Agents 的检索评分函数（γ=0.995，三项等权） | **A**                                   |
| 记忆只追加、不整体进 prompt        | 同上（记忆流只增不减，检索取 top-k）                  | **A**                                   |
| 结构化事实层（掌握度 / 连续对错）  | 「语义检索会漏掉关键事实，结构化事实每次都加载」      | **C**                                   |
| 检索设 topK + 最小阈值             | 「无关回忆浪费 token 且让角色混乱」                   | **C**                                   |
| 规则化 importance（降级路径）      | 论文用 LLM 打分；本项目为守降级承诺而设替身           | **A** + 本项目取舍                      |
| 模型只做表达，不裁决玩法           | 「让确定性检查负责 pass/fail」                        | **D**（沿用 playtest-agent 的外部印证） |
| 治理武器落在对话上                 | 内部盘点约束 3：「在这个稀缺武器的新战场打」          | 内部材料                                |

### 4.4 风险与对策（写在开工前）

| #   | 风险                                       | 概率   | 对策                                                                  |
| --- | ------------------------------------------ | ------ | --------------------------------------------------------------------- |
| R1  | **NPC 沦为聊天挂件**（有互动但不影响玩法） | **高** | 成功标准 N2 硬性要求"选域决策改变题集"；写进 PRD §5                   |
| R2  | **改既有引擎破坏红线**                     | 中     | NPC 只读引擎；新增代码独立目录；改完既有 59 单测 + e2e 必须全绿       |
| R3  | **又一次"引擎语义混用"**                   | 中     | NPC 记忆/意图模型**独立**于 `lib/engine/*`；两者只通过**事件**对接    |
| R4  | **降级路径与有模型路径行为差异大**         | 中     | importance 双打分落在同一 [1,10] 标度；同 seed 对比两份报告           |
| R5  | **成本失控**（NPC 是长期消耗品）           | 中     | 每次对话的 token 入账；场景级预算熔断（可复用 playtest-agent 的做法） |
| R6  | **多用户记忆串味**                         | 中     | 记忆按用户隔离（本地存储 key 区分）；这是治理武器的用武之地           |
| R7  | 调研的 γ=0.995 不适合"每天 5 题"节奏       | 中     | 实现后按真实使用频率标定；论文是小游戏沙盒，节奏不同                  |
| R8  | aiwarden 侧无 NPC 相关工具                 | 中     | 治理接入是**可选增强**，不作为立项前提（裁决草案 14）                 |

### 4.5 Roadmap 过滤器

| 吸收                                | 不吸收                   |
| ----------------------------------- | ------------------------ |
| 记忆按用户隔离 + 每次对话留成本证据 | 向量数据库 / 嵌入检索    |
| 规则化 importance（降级路径）       | 反思机制（高层洞见）     |
| topK + 最小相似度阈值               | 自由形态对话（聊天挂件） |
| 预算熔断 + 审计留痕                 | 多 NPC 编排 / 群体智能   |
| 同 seed 可复现                      | 玩家间的 NPC 状态共享    |
