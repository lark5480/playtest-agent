## 1. 调研说明

### 1.1 调研对象与前提

**要回答的问题**：「AI NPC 的记忆与对话」这个方向，是**挤爆**了还是**还有空位**？
若挤爆，通识局加 NPC 这条路就不该走（门 G1 的止损条件）。

**前提**：

- 宿主是**已有游戏**（通识局），不是新造一款叙事游戏；
- 目标是补《AI 游戏作品》灵感库的 **03 类**（故事与 AI NPC）；
- 差异化**不来自**"NPC 多聪明"，而来自**治理证据**（见立项论证 §2.2）。

### 1.2 方法

- 检索：web 搜索（英文关键词），优先一手来源（论文、官方文档、公开仓库）；
- 二手综述只作线索，其转述的数字一律降级标注；
- **未实测任何竞品** —— 本文不含"我跑过它"的断言。

### 1.3 检索关键词

`AI NPC conversational memory long-term memory game character consistency architecture` /
`Generative Agents memory retrieval recency importance reflection`

### 1.4 一句话结论

> **架构层已被验证清楚（Generative Agents 是公认蓝图），产品层仍空。**
> "记忆流 + recency/importance/relevance 三段检索 + 反思" 已是**标准做法**，
> 意味着**光有这套架构不构成差异化**；
> 而**"每次对话都有可审计的成本与状态证据"这一层，本文查到的所有来源都没做**。
> → 差异化必须落在后者。

## 3. 学术锚点：Generative Agents 的记忆架构

> **来源**：Park, J. S., O'Brien, J. C., Cai, C. J., Morris, M. R., Liang, P., & Bernstein, M. S. (2023).
> _Generative Agents: Interactive Simulacra of Human Behavior._ UIST 2023.
> DOI: 10.1145/3586183.3606763　**证据等级：A（一手论文）**

这是本项目的**核心参考**，三个部件：

### 3.1 记忆流（Memory Stream）

- 只追加（append-only）的自然语言观察记录，每条带**时间戳**、**重要性分**、**嵌入向量**；
- 随模拟持续增长，**永不整体进 prompt** —— 每次决策只检索小子集。

### 3.2 检索评分（Retrieval Scoring）—— 本项目 `memory/retrieve.ts` 的直接依据

```
score = α_rec · recency + α_imp · importance + α_rel · relevance
```

| 分量                     | 定义                               | 论文参数                                          |
| ------------------------ | ---------------------------------- | ------------------------------------------------- |
| **recency**（近因性）    | 距上次访问的时间，**指数衰减**     | `recency = γ^(距上次访问的小时数)`，**γ = 0.995** |
| **importance**（重要性） | **由 LLM 打分**该记忆的意义大小    | 约 **1–10** 分                                    |
| **relevance**（相关性）  | 查询嵌入与记忆嵌入的**余弦相似度** | —                                                 |

**三个分量各自 min-max 归一到 [0,1] 后相加，论文中权重相等（α = 1）。**

> **可直接落地的细节**：取 top-k；论文用 25 个 agent 跑两天模拟，靠**消融实验**
> （去掉 reflection / planning / memory）隔离各部件贡献，再做**人工评价**。

### 3.3 反思（Reflection）

- **触发条件**：近期记忆的 **importance 之和超过阈值**；
- **流程**：Agent 暂停 → 自问"最近发生了什么值得注意的事" → 检索证据 → 综合出高层洞见
  → **把洞见作为新记忆写回记忆流**（因此洞见本身也能被检索与再反思，形成抽象层级）；
- 洞见与检索结果共同驱动**规划**，形成"观察→检索→反思→规划"的闭环。

### 3.4 与本项目的取舍

论文的三分量里，**importance 依赖 LLM 打分** —— 但本项目要求"降级是一等公民"
（无模型也能玩）。因此本项目的**降级路径**下 importance 必须有**规则化的替身**
（见 §5.2）。这是本项目与论文的**唯一实质偏离**，且是有意的。

## 4. 工程实践的分层记忆架构

> **来源**：技术综述《Giving LLM NPCs a Memory That Lasts Past One Conversation》
> **证据等级：C（技术综述）** —— 细节需回溯原始来源，但分层思路与本项目设计一致。

一个典型的 LLM NPC 系统分**四个模块**：

```
上下文构建器 → LLM 接口 → 响应解析器 → 记忆管理器
```

**关键设计**：**记忆管理器不直接与模型对话**。它的职责是给上下文构建器
**几百 token 的正确历史**，在严格 token 预算内保持 prompt 小、角色连续。

四层记忆：

| 层             | 做法                                                                                       | 关键参数                                                                 |
| -------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| **短期缓冲**   | 最近消息的滚动缓冲，带角色标签与时间戳                                                     | **10–20 对**消息足够自然流畅                                             |
| **溢出摘要**   | 缓冲满时，把最早的压缩成**两三句话**的摘要放在历史顶部                                     | 只在溢出时多一次模型调用                                                 |
| **向量检索**   | 会话结束时嵌入并存档（摘要 + 时间戳 + NPC id）；新会话开始时嵌入玩家开场白，取最相近的召回 | 存**3–5 对消息的片段**（按主题分组）；设**最小相似度** + **上限 2–4 条** |
| **结构化事实** | 语义检索会漏掉"每次都相关"的事实：玩家名字、做过的承诺、与 NPC 的立场                      | 会话后抽成带标签的记录，**每次都加载**（不看主题）                       |

> **两个反直觉的要点**（值得写进设计）：
> ① 「整段会话检索太松，单条消息又撑爆索引」→ 按主题切成 3–5 对的片段；
> ② 「语义检索**会漏掉关键事实**」→ 所以结构化事实层是**必需的补充**，不是可选项。

### 4.1 情景记忆 vs 语义记忆

> **证据等级：C**

| 类型                     | 记什么                       | 例子                           |
| ------------------------ | ---------------------------- | ------------------------------ |
| **情景记忆**（episodic） | 具体的时间顺序事件           | 「玩家周二午夜偷了我的银圣杯」 |
| **语义记忆**（semantic） | 从情景中提炼的**一般化认知** | 「玩家不可信，有偷窃前科」     |

把情景记忆**逐步蒸馏**成语义信念，好处是**不必回忆每一句说过的话**，
既控制 token 足迹，又保留关系的情感本质。

### 4.2 记忆衰减（Decay）

> 「有些系统在此之上加**记忆衰减**，让较旧、不重要的记忆随时间淡出，
> 使检索保持聚焦。」　**证据等级：C**

这与 §3.2 的 `γ = 0.995` 指数衰减是同一机制的两个说法：
**近因性本身就是一种衰减**。

## 5. 对通识局 NPC 的设计推论

> 本节是**从上面的证据推出**的结论，不是引用的结论。

### 5.1 记忆模型：三层，而不是一套

通识局的场景比通用 NPC 简单得多（**不需要向量数据库**，也不需要多主题会话），
所以直接照搬四层是过度设计。推论：

```
tongshi-ju/lib/npc/memory/
├─ facts/        结构化事实层（必须）：每域掌握度 / 连续对错 / 偏好域
├─ episodes/     情景层（必须）：最近 N 次答题事件（含时间戳 + 重要度）
└─ retrieve.ts   检索：按 §3.2 的三段式打分，但 relevance 用**结构化匹配**替代嵌入
```

**为什么 relevance 不用嵌入**：通识局的"相关"是**结构化的** ——
"这题属于哪个域"是确定的，不需要语义相似度。
用嵌入反而引入一个外部依赖与不确定性。

### 5.2 importance 的降级替身（论文与本项目的偏离点）

论文的 importance 由 LLM 打 1–10 分。本项目要求**无模型也能玩**，故：

| 场景               | importance 来源                                                   |
| ------------------ | ----------------------------------------------------------------- |
| 有模型             | LLM 打分（遵循论文）                                              |
| **降级（无模型）** | **规则打分**：答错 > 首次答对新域 > 重复答对；连击/错题本状态加权 |

**两种打分都必须落在同一 [1,10] 标度**，否则降级前后行为不可比。

### 5.3 反思机制：先不做

论文的反思需要"自问—检索—综合—写回"四步，每次都调模型。
通识局的 NPC 只需"针对薄弱域出题 + 点评"，**不需要产生高层洞见**。

**结论**：反思列为**后续项**，MVP 只做**记忆流 + 检索 + 结构化事实**。
理由：反思是"让 NPC 更像人"的增强，而本项目的差异化在**治理证据**，不在拟人度。

| 类别         | 代表                                               | 证据等级 | 与本项目的关系                               |

| **游戏内建** | 传统对话树 / 任务旗标                              | **B**    | 本项目的对照基线                             |

### 6.1 饱和度判断（门 G1 的判据）

| 判据                       | 结论       | 依据                                                           |
| -------------------------- | ---------- | -------------------------------------------------------------- |
| 架构层                     | **已成熟** | Generative Agents 已被广泛复制（三段检索是"reference design"） |
| 落地成本                   | **已降低** | 分层记忆的做法有大量公开实现                                   |
| **"每步有治理证据"这一层** | **空**     | 本文查到的所有来源**均未涉及**成本归因 / 配额 / 续跑 / 审计    |

**结论：架构不构成差异化 → 差异化必须落在治理层。**
→ 与 playtest-agent 是**同一套治理武器的第二个战场**（见立项论证 §2.2）。
→ **通过门 G1，继续立项。**

但要诚实：**"空"不等于"有价值"** —— 价值必须由自己的可复现证据支撑。
